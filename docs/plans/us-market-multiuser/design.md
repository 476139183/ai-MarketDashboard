# 美股多人看板设计

## 1. 决策表

| ID | 决策点 | 候选 | 暂定 | Why |
|---|---|---|---|---|
| D1 | 产品形态 | 手机 H5 / 小程序 / 原生 App | 响应式 H5 | 首期手机和电脑通过链接访问 |
| D2 | 注册登录 | 密码 / 手机验证码 / 第三方 | 国内手机号验证码，注册与登录合并 | 用户明确要求手机登录 |
| D3 | 行情授权 | 现有个人数据 / 商用授权 | 确认供应商的多人展示及衍生指标许可后接入 | 个人接口权限不等于多人分发权限 |
| D4 | 行情处理 | 每用户单独请求 / 服务端集中采集 | 单份行情集中采集计算，多个用户共用 | 避免用户数放大上游请求 |
| D5 | 数据传输 | 固定轮询 / SSE / WebSocket | MVP 轮询服务端缓存，后续按负载升级 | 四只股票、数百用户先保持简单 |
| D6 | 数据存储 | 本机文件 / 托管数据库 | PostgreSQL + Redis（或同等托管服务） | 保存账户和自选、管理登录状态与限流 |
| D7 | 运行部署 | 用户电脑临时隧道 / 云服务器 | 云端长期服务 + HTTPS + 受管数据库 | 面向多人不能依赖个人电脑持续开机 |
| D8 | 策略 | 当前研究输出 / 新建未经验证实盘指令 | 优先展示价格、方向观察、强度与数据质量 | 不将研究性指标包装成可靠买卖建议 |
| D9 | 访问范围 | 全网直接开放 / 邀请制 | 开发期邀请制；公测范围另定 | 先验证权限、数据和成本 |

## 2. 契约边界

- 股票：首期 SNDK、SKHY、MU、NVDA；用户选择与排序相互隔离。
- 时间：界面以北京时间展示并标明盘前、盘中、盘后及行情时间；按美东交易日与交易所日历处理夏令时、假日及提前收盘。
- 行情：每次输出带来源、事件时间、接收时间、时段、质量状态；停更、超时、无量及数据延迟明确展示，不能沿用旧值作为实时价。
- 信号：15 分钟结构由完整已结束的 K 线或明确标记未完成的数据生成；强度是规则指标，不宣称胜率；只展示经验证的功能。首次同向记录按标的、时段、方向和策略版本区分。
- 鉴权：验证码短有效期、一次性、尝试次数限制；IP、设备、号码分别限频；敏感配置留在服务端；会话失效与登出可撤销。
- 多人：用户只能读写自己的自选与账户资料；客户端不能访问供应商密钥。
- 数据最小化：手机号用于登录和必要风控；界面展示隐私政策并提供注销渠道，处理方案经适用地区的法律与安全核查。
- 安全：全站 HTTPS；日志不记录验证码、密钥及完整手机号；查询和告警不向第三方暴露敏感信息。

## 3. Trade-off

### D3：行情供应商

- 现有 Nasdaq 公开页面接口和 Alpaca 免费 IEX：可用于研究或个人测试；多人产品的展示、实时性、历史数据及衍生指标授权均需逐项确认。
- 商用行情 API：有合同和稳定性支持；费用可能包括使用人数、行情来源和分发权限。
- 决策：先核实合同与费用，再选生产源；没有授权前仅用可分发的模拟或测试数据搭建功能。

### D5：刷新机制

- 客户端轮询统一后端缓存：适合首期规模；页面显示的行情时间而非请求时间决定新鲜度。
- SSE/WebSocket：更及时但增加连接数、断线和恢复复杂度；达到观测到的轮询瓶颈后再评估。

## 4. 验收指标

- 首期假设：50–500 注册用户、同时在线约 50 人，实际目标待确认；移动端和桌面端可用。
- 用户：验证码过期、错误、限频、登出及多账户自选隔离通过自动化测试；短信供应商错误不泄露验证码。
- 行情：四只股票各显示合法来源、行情时间、当前交易时段；缺行情或过期不可显示为实时可操作信号。
- 调度：15 分钟结构分析按美东交易时段对齐；价格刷新频率由授权及实际供应商能力决定。
- 性能目标（待压测校准）：50 并发用户下缓存读取接口 p95 < 500 ms（不包含首次上游获取）；页面 p95 < 2 秒，使用预设环境与网络条件实测。
- 运营：至少有错误监控、短信额度告警、数据库备份与恢复演练；采集停止时用户可见状态。

## 5. 范围

- in scope：国内手机号验证码、账户、自选、多股行情展示、方向与强度研究结果、云端定时运行、移动端访问。
- out of scope：自动交易或代下单、证券账户绑定、承诺收益、海外短信、付费订阅和无限股票池；均需单独定义。
- 未决：实际并发、行情延迟要求、展示与信号授权、主体及短信资质、域名与部署地区、服务预算和内部/公开使用范围。
