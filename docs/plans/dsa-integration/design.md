# DSA 接入设计

## 1. 决策表
| ID | 决策 | 选定 | Why |
|---|---|---|---|
| D1 | 集成方式 | 独立 DSA 服务，通过 HTTP 调用 | 保持本地标准库运行方式，隔离上游依赖 |
| D2 | 日线 | 配置后优先 DSA，失败回退原行情并披露 | 复用数据聚合；不阻断原看板 |
| D3 | AI 报告 | 手动异步提交、查询任务、展示报告 | 避免刷新触发重复模型调用 |
| D4 | 凭证与副作用 | 服务端环境变量；notify=false | 不向浏览器提供凭证、不自动推送 |
| D5 | 网页布局 | 侧栏自选、行情图、研究面板；手机纵向展示 | 同一页面适配桌面和手机 |
| D6 | 运行入口 | 单命令启动独立 DSA 与网页服务，默认 8766 | 避免占用原有 8765 服务，集中管理生命周期 |

## 2. 契约边界
- DSA 历史行情只请求 daily，日期与 OHLCV 校验后映射为美东日线；当天日线不参与趋势。
- K 线须非空、标的一致、日期唯一、OHLC 合法；缺失成交量保留为空。
- 仅在美股日线读取处接入，现有分钟线与 A 股历史研究口径不变；独立研究页允许 A 股/美股代码读取 DSA 数据和报告。
- DSA 未配置时原信号行为不变；SIGNAL_CACHE=1 时不访问 DSA。
- 上游日线 API 不返回实际供应商及复权口径，只披露 DSA 服务来源，不臆造交易所或复权信息。
- AI 只经 POST 手动触发，notify=false；状态 GET 不重新提交。重复任务复用 existing_task_id。
- 模型/新闻服务凭证在 DSA 服务配置；本地只存服务地址与可选会话 Cookie。
- 用户当前选择先启用行情，AI 模型稍后配置；页面用真实健康状态与主模型配置状态分别控制行情和报告入口。
- 图表使用本地 Lightweight Charts 5.2.1；显示所选日线范围，额外预热历史只参与均线计算。自选只存当前浏览器，不新增账户。

## 3. Trade-off
- 直接复制数据模块依赖上游配置、数据库和整个适配层；HTTP 接入保持上游升级边界，代价是需要运行额外服务。
- 日线经校验后使用；失败回退保留原因；不将 AI 建议替换原策略。

## 4. 验收指标
- HTTP 传输层契约测试覆盖日线映射、错误、空数据、错误标的、非法价格、任务重复与完成；真实服务另外验证日线与主模型配置状态。
- 回归覆盖 DSA 未配置/失败、原分钟接口不访问 DSA、未收盘日线排除。
- 页面支持日线读取、报告提交、任务恢复查询、失败状态；报告文本不能执行 HTML。
- 上游基线：ZhuLinsen/daily_stock_analysis db0570edd008a319d7eff14eda3bc0ef9da620eb。
- 实际 Chromium 验收：1440px / 390px 无横向页面溢出，NVDA / 600519 行情成功绘制，模型未配置时不触发模型调用。

## 5. 范围
- in scope：日 K、日线趋势接入、手动 AI 报告、异步状态、独立研究页、启动与配置说明。
- out of scope：分钟源替换、自动推送、自动交易、多人账户、复制整套工作台。
